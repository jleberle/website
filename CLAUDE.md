## Publishing is `scripts/ship.sh`, not `git commit`

`ship.sh` runs the preflight gate and **refuses to commit or push** if it
fails, leaving the tree untouched. Committing by hand bypasses that gate
entirely. Pushing *is* deploying — Cloudflare Workers Builds builds from the
push — so a bad commit is a bad live site, with no separate deploy step to
catch it.

`ship.sh` uses `git add -A`, which is why it prints every pending change and
asks first: unrelated in-progress work will otherwise ride along. `--yes`
skips that prompt; only use it when you have just checked `git status`.

Check severity is a two-tier system (`✗` blocking vs `⚠` advisory) and the
distinction is deliberate — `docs/operations.md` explains where the line is
drawn. Note that **CI fails on advisories** even though local ship does not.

## Drafts live outside this repo

`~/Notes/07 Blog/Drafts/` in the Obsidian vault (override:
`WEBSITE_DRAFTS_DIR`). `scripts/newpost.sh` creates them there;
`scripts/publish-draft.sh` moves them in. There is no `.obsidian/` here and
there should not be. A draft that "disappeared" is in the vault.

The Templater templates in `templates/obsidian/` are a versioned copy of what
Obsidian loads from `~/Notes/Meta/templates/Website/`; `sync-templates.sh`
reconciles them and preflight warns on drift. They only *prompt* —
`newpost.sh` is the single implementation of the slug rule and field order, so
fix format bugs there, not in the template.

## content/cv/ is generated by another repo

`content/cv/index.md` and `content/cv/cv.pdf` are built by `~/git/cv`'s
Makefile, which writes straight into this bundle. Hand edits survive a commit
and are silently overwritten by the next `make publish` over there. Change the
section partials in `~/git/cv` instead.

`content/courses/*/index.md` is the same arrangement via
`~/git/syllabi/publish-web.py`, with the same warning.

## Cross-repo feed contract with ~/git/micro-theme

`layouts/reading.rss.xml` generates the `Started reading: ` /
`Finished reading: ` prefixes that Micro.blog's autotagging keys off, and that
`~/git/micro-theme`'s `index.html` parses to build its homepage sections.
Reword either prefix and the theme's sections silently empty — no error on
either side. `scripts/checks/feed-lint.py` asserts both strings for exactly
this reason; if you change them, change the theme and the lint in the same
pass.

`📚` in that feed is a **delimiter, not decoration** — the theme splits
headline from notes on a newline first, then on `📚`. Moving it runs the notes
into the title link.

`hugo.yaml`'s reading feed limit must stay ≳8: Micro.blog imports by polling,
so an item that scrolls out of the window before the next poll is never
imported at all, silently. The reasoning and the current event rate are in a
comment there.

## Things that break without erroring

- **Editing an inline `<script>` breaks its CSP hash.** The hash is a drift
  guard, not a tamper check — an edited script stops matching and the browser
  refuses to run it, with nothing failing at build time. Re-run
  `scripts/csp-hashes.sh`.
- **`scripts/writing-log.py`'s counting key must never change.** Changing it
  orphans every recorded observation; the file says so at the definition.
  Relatedly, `log-writing.sh` resets `--mixed`, never `--hard` — a `--hard`
  there destroys unrelated working-tree state.
- **Runtime-injected markup is invisible to `curl`.** Anything added by JS
  needs a browser to verify, not a fetch.

## Verification

```bash
scripts/doctor.sh        # is this CHECKOUT configured correctly (not: are tools installed)
scripts/preflight.sh     # the local gate, no commit
scripts/preflight.sh --full   # everything CI will say
npm run test:axe         # accessibility pass over public/
```

Tool *installation* is `~/git/dotfiles`' job (`dots brew-check`) — `doctor.sh`
used to duplicate it and deliberately no longer does.
